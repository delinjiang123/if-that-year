## 一、v0.16.1 → v0.20.0 到底变了什么（事实清单）

1. **已上线。** `https://if-that-year.pages.dev` 可访问（本次已打开核对，标题为“如果那年 · 另一条路 —— 人生分岔模拟”），Cloudflare Pages 推 main 自动部署。上一版“未上线”批评销账。
2. **埋点已开启，但存储未确认。** v0.17.0 起客户端按六类事件（game_start / card_pick / glimpse / game_complete / share_click / lives_view）发到同源收集端 `functions/api/collect.js`，不记 IP；但存储需要作者在 Cloudflare 后台手动绑 KV namespace（`IFY_ANALYTICS_KV`），未绑时“只收不存”。**绑没绑，仓库里看不出来——这是现在最该确认的一件事（见改进 P0-1）。**
3. **序章（c2000 试点）。** 2000 年生不再从 22 岁开局：来历、童年 4 幕、少年 2 幕、16 岁分岔、17–21 岁 4 幕，共 12 幕 + 6 幕处境线；入学处境（上学 / 边上学边帮工 / 没进过学堂带夜校线）由年代×家底按种子发放，童年的三个记号（同桌、河、树）会在成年段与影子瞥视里回响；出身牌并入序章、数值与钩子旗不丢。其余三个年代本轮仍是旧开局（抽牌+选路）。
4. **地基与内核。** 结构化人生账本（ledger，所有事件 / 分岔 / 进程 / 状态流转入账，判词、特殊结局证据、结算都改读账本）；随机流分家（进程流 `#world` / 环境流 `#ambient` / 叙事流 / 序章流四股派生）；统一 storylet 层与调度五层仲裁（危机抢占 → 稀有与链推进 → 温度平淡年 → saliency → 微年）。注意兼容裁定：**种子语义自 v0.18 起变更**，旧分享链接打开同一种子复现的是“同一个起点”而不是“同一局”——对已发出的旧链接和老玩家的对照体验，这是一次有意的破坏性变更，已在 DEVLOG 留痕，但仍会在传播端产生困惑。
5. **父母进程。** 父母身体不再等事件抽中：按父母那一代人的队列寿命标定出生年龄带与寿命，需照护 → 住院 → 离世由进程越线发作。关系线也进进程（处了多年的关系会有说法，不再冻在“恋爱中”几十年）。
6. **职业语境与活计形态。** 全池扫描登记预设行当 319 条、新立 20 面入行旗与 10 条入行拍、挂门 208 条；`formOf()` 按本局事实派生职业形态，终身口吻条目须本线是主线才出。项目自报盲读：教师、店主小升，**农民线仍垫底**（形态门只能拦不能造，项目自己也如实记了）。
7. **死亡分布按出生世代重标（本轮最大的一次口径变动）。** 旧口径（四世代拉平：早夭约 3.24%、活到 80 约 90.47%）作废；新口径按国家统计局普查生命表、联合国 WPP2024 等公开研究沿队列近似标定：v0.20 收尾 16000 局实测早夭约 13.28%、60–79 岁死亡约 32.53%、活到 80 约 54.20%；分世代活满 80：1955 年生约 46%、1965 年生约 48%、1978 年生约 56%、2000 年生约 66%。c1955 中段与活满两档贴边出带（质量关 13 PASS / 1 WARN，项目如实留痕）。
8. **结算重做。** 结算事实过滤（F1–F5）+ 九槽结算（落脚、陪伴、钱的收场、手艺事业、子女线、父母线、没办完的事、影子代价、你留的话）逐槽读账本拼装；特殊结局除原条件外须凑满 2 个独立证据点，任一特殊结局命中率从约 12% 降到 4.97%；年表新增“差一步”呈现（只差一项的结局 / 分岔以空心剪影出并写明差什么，上限 6 个）——但分享卡未同步此项，项目已登记在案。
9. **出国线与退休相位补齐。** abroad 正文包 29 条（四种去向原型、早 / 中 / 晚三段，只写原型不写国名）；工作线有退休相位（在职 → 半退 → 退休，返聘可回流）。
10. **新玩家默认自动推进改为“关”。** v0.17 定案（老玩家既有设置不动，完局后结算页提示可开平年自动）。这推翻了 v0.7 基于停顿统计得出的“默认全程”结论——项目还在用脚投票调这个参数，说明其对完局率的真实影响仍未知，只能等埋点读数裁决。
11. **内容总量微涨，结构重组。** 全库 2220 条目（validate-state 口径；ID 唯一 2251），内容按领域重组到 `src/content/`（pool / lines / era / rare / prologue）；engine 先机械拆分再真模块化（14 分片、IFY 命名空间），质量关一键全检（validate-state + validate-storylet + 状态线断言 + 链选择检查 + 确定性 + 旧档 + 跑批）。
12. **仍未实现（与 v0.16.1 清单几乎一致）：** 珍藏付费、影子完整推演引擎（仍为查表文本）、浪潮事件组、日文版、B 端引导版、故事墙。

## 二、立意复评：序章补上了“来历”，但只补了一个年代

序章是立意层面的真进步。旧版的人生从 22 岁“选路线”开始，默认了人人站在同一起跑线选路——序章把这个假设打破了：你读不读书、进没进过学堂，很大程度不是你选的，是年代和家底发的牌。16 岁分岔是全序章唯一的大选择，之前都是“被讲起的来历”，这个顺序本身就是立意：先有来历，后有选择。这让“如果那年”的反事实不再只是成年人的后悔药，也包含“有些路一开始就不在选项里”的诚实。

但两个问题必须指出：

- **年代不对称正在变成体验不对称。** 只有 2000 年生有完整序章，其余三个年代还是“抽牌+选路”的旧开局。四档年代本是这个产品区别于竞品的资产（给父母那代人重走一遍，是很强的情感用法），现在最新的叙事资源明显向最年轻的一档倾斜。序章“随年代逐轮补齐”是计划，但按现在两天四个大版本的节奏，补齐三个年代序章的成本会被低估——每个年代的童年都不能互相套用，这是三份完整的写作工程。
- **序章拉长了“第一分钟”。** c2000 玩家要走完 12 幕才汇入五路线。项目 v0.20 的公开验（20 局审计 + 4 名全新评审）说首屏一句话测试 4/4 能复述核心玩法（含影子机制），这缓解了担忧，但样本太小（4 人），不能当作“第一分钟成立”的证据。真正的检验仍是埋点里的 game_start → game_complete 漏斗按年代拆分后的数字。

## 三、游戏性复评：从“图文幻灯片”到“有系统的叙事模拟”，但还没到“有策略”

上一版 6.5 分的主要扣分项是“系统薄”：选择靠标记回响撑着，父母生死靠事件抽签，职业靠文本预设穿帮，结算靠数值形状拼词。这四项在这一轮里全部被系统化了：

- 账本 + 四股随机流 + 五层调度，让“一局”从一串抽卡变成了有进程、有账目的人生；危机抢占实测（4000 局里危机触发 530 次、451 次同年有合格稀有候选）说明调度不是摆设。
- 父母进程把全游戏最重的情感线（照护、住院、离世）从“抽没抽到”改成“迟早会走到哪一步”，这是叙事可信度的质变，也是玩家最可能记住一局的来源。
- 状态线对齐（v0.19 把 2936 次扫描命中修到真缺陷 0）和职业对账（动态违规 0）延续了这个项目罕见的工程纪律——对内容型产品来说，不穿帮就是游戏性的一部分。

仍挂账的扣分项：

1. **大分岔仍是 8+1 个，决策密度没变。** 五层调度让“年份之间的事件”更聪明了，但玩家亲手做的大决定还是那几个。进程拍还变多了（人均屏数 7.24 → 9.18，项目自己记了“时长账再涨、续挂账”）——系统越厚，被动阅读的比例反而越高。这个张力没有被解决，只是被管理得更好了。
2. **影子仍是查表。** 两轮大改之后，核心卖点的实现方式仍是 README“未实现”清单的原话：影子完整推演引擎（现为查表文本）。账本和随机流分家之后，做双线推演的地基其实比以前近了；但在做出来之前，对外表述必须继续停在“瞥见剪影”，不能用“平行线继续运行”去暗示完整模拟——README 定位语里恰好就是这句，建议改口径或加注。
3. **死亡变重是一把双刃剑。** 活满 80 从约 90% 掉到约 54%，早夭从约 3% 涨到约 13%（1955 年生局约 19.6% 在 60 岁前结束）。真实性、可信度、B 端说服力都涨了；但近半数的局会“提前结束”，对期待“完整活完一生”的休闲玩家，挫败感和完局观感（注意：埋点的 game_complete 含死亡结算，所以完局率不会因此难看，但玩家主观的“没活完”感会）需要用试玩原话验证，不能只看模拟分布。项目“早夭不是失败态、文案不贬早逝”的口径是对的，执行效果要看真人反馈。
4. **判词形状的历史问题只报未修。** v0.19 日志如实记了：判词登顶仍是关系 48.0%、金钱垫底 1.0%，“形状未动只报数”。九槽结算分担了判词的叙事压力（判词从“一局的全部总结”降为“收尾一行”），这算是聪明的绕行，但不是修复。
5. **农民 / 务农线仍是全库最薄的一条。** 两轮职业专项后项目自报盲读农民仍垫底。对一个人群画像本就偏城市白领的产品，这是三方审稿老账的延续，不是新问题——但每轮都“如实记”而不补供给，记的次数多了就变成态度问题。下一轮内容配额应明确给务农线一个硬数字。

与项目自家盲审的交叉验证：v0.19–v0.20 两批全新评审面板中位大体是故事最高、逻辑最低（v0.20 公开验：逻辑 3.5–4、故事 6、可信 4.5–6、游戏 4.5–5、耐玩 4–6，口径见 DEVLOG）。方向与本评价一致：叙事是强项，系统逻辑与耐玩是短板。这不是客套，是两边独立得出的同向结论，可信度因此更高。

## 四、裂变性复评：从“不可测”到“可测”，但还没到“已测”

进步是实质性的：站点上线 + 埋点开启，意味着增长文档里那张指标表（完局率、分享率、每千名玩家有效分享卡、同局链接开局率、珍藏转化）第一次有了产生数字的可能。v0.20 公开验里“最想截图的一局”被两名评审独立撞选（跨十六年的猫线），说明能产生截图冲动的内容确实存在，不是纯设计推论。

但必须泼三盆冷水：

1. **KV 绑定未确认 = 数据可能仍是 0。** 如果 Cloudflare 后台那一步没做，过去这些天所有玩家的事件都“只收不存、静默丢弃”。上线不等于有数据，这是当前优先级最高的一个确认动作，没有之一。
2. **裂变闭环的老断点一个没补。** 按 v0.20 的 README 核对：故事墙仍在未实现清单；分享台描述与 v0.16 相同（判词卡 / 流水账卡、系统分享、复制文案），没有挑战落地横幅、没有完局自动对照卡的新增表述；“差一步”剪影也还没同步到分享卡。也就是说，被挑战者点进链接时的体验、以及第二张卡（对照卡）的生产，仍靠手动。
3. **种子语义变更对裂变是隐性成本。** v0.18 起旧链接复现的是起点而非同一局。在裂变语境里，“我把我的局发给你，你打开却不是我那一局”会伤害对照感。版本位 `k=3` 的处理是工程上正确的裁定，但产品端需要一句话向玩家交代（例如落地横幅写明“同一起点，两条人生”），而不是让玩家自己发现对不上。

**判断不变：** 上线后 4 周只看三个数——完局率、分享率、同局链接开局率。健康线沿用增长文档（完局 ≥55%、分享 ≥15%、同局开局率 ≥35%、K ≥0.2）。任何讨论如果不能落到这三个数的读数上，都是在用开发代替验证。

## 五、未来价值与变现复评：价值在涨，变现没动——四天里最刺眼的不平衡

从 v0.16.1 到 v0.20.0 是 2026-11-01 到 11-02 两天内的四个大版本：地基、内核、世代死亡标定、内容重组、真模块化。这种产能本身就是价值证明——内容库（2220 条）+ 账本 / 状态矩阵 / storylet 这套可维护的系统 + 已上线的站点 + 一套有公开研究出处的世代死亡标定数据，合起来是一份后来者很难快速复制的资产。尤其是死亡标定和父母进程这类“把真实数据做进叙事规则”的工作，是 B 端（学校生涯教育、咨询、企业关怀）最认的东西，可信度资产比上一版更厚了（公开验可信维度 4.5–6，为各维最高之一）。

但变现一栏必须给差评，不是因为数字难看，而是因为**根本没有数字**：

- 未实现清单两轮未变：珍藏付费没有、B 端引导版没有、日文版没有、故事墙没有。
- 上线已经数天（以 11-02 上线计），如果 KV 还没绑，连“有没有人玩完、玩完后有没有分享”都不知道，珍藏付费的 A/B、B 端小样的谈判弹药就都无从谈起。
- 这个项目的历史模式正在形成：用一轮接一轮的大改造回应评审和自我审计。每一轮都言之成理，但“做产品”和“做验证”的投入比已经严重失衡。**下一轮如果还是 v0.21 的功能清单而不是第一份漏斗读数，这个项目最大的风险就不再是产品不行，而是永远不去问市场。**

因此变现评分维持 4.0：潜力构成没变（C 端珍藏是小钱、主题包中等、B 端授权是大钱慢钱、广告最差、订阅不适合），但实现进度为零，且时间已经开始计息。未来价值从 7.0 上调到 7.5，全部来自上线与系统资产，不来自商业证据——如果到 2026 年 12 月初（上线满 4 周）仍拿不出三项基本读数，这个上调应撤回。

## 六、完整优缺点（v0.20.0 更新版）

### 优点（新增 / 升级标 ◆）

1. 题眼真、机制差异化真（影子人生），两轮大改未稀释。
2. ◆ 已上线、埋点已开启：从“设计评审对象”变成“可被数据评审的产品”。
3. ◆ 确定性引擎升级为四股随机流 + 结构化账本 + 五层调度：可复现、可审计、后果有账可查。
4. ◆ 父母进程与世代死亡标定：把真实队列数据做进叙事规则，可信度是同类产品罕有资产。
5. ◆ 序章（c2000）：来历先于选择，立意补厚；童年记号有成年回响，不是过场动画。
6. 状态矩阵、校验门、质量关全检成为常设：不穿帮靠制度，不靠人品。
7. ◆ 九槽结算 + “差一步”剪影：在不搞收集焦虑的前提下，给了玩家“下次想凑齐什么”的温和目标。
8. 纯静态 + 同源收集端：分发与数据成本都极低，扛流量的架构结论不变。
9. 开发纪律罕见地诚实：贴边出带、农民线垫底、镜像事故、试改撤回都如实记进 DEVLOG——这种记录习惯本身是长期资产。

### 缺点（仍挂账标 ●，新增标 ○）

1. ● 变现零进度：珍藏、B 端、日文、故事墙两轮大改全部未动，商业验证没有启动。
2. ○ 数据链未闭环确认：KV 绑定状态不明，上线数日可能仍无任何留存数据。
3. ● 裂变闭环断点未补：挑战横幅、对照卡、卡面 A/B 未见落地表述；故事墙仍是计划。
4. ● 影子仍是查表文本，与 README“平行线继续运行”的表述之间有口径落差。
5. ● 决策密度未变：大分岔仍 8+1，进程拍变多后单局时长再涨（项目自记“续挂账”）。
6. ○ 年代体验不对称：只有 c2000 有序章，其余三档是旧开局；且 c2000 玩家进五路线前的路变长了。
7. ○ 死亡显著变重：约 46% 的局活不到 80，c1955 约两成局 60 岁前结束——真实，但对休闲玩家的观感未经真人验证；c1955 两档贴边出带（WARN）仍在。
8. ● 判词形状坍缩只报未修（关系登顶 48%、金钱垫底 1%，v0.19 口径），九槽是绕行不是修复。
9. ● 农民 / 务农线连续两轮垫底，内容配额没有硬性纠偏。
10. ○ 种子语义破坏性变更的玩家端交代缺位，旧同局链接的对照体验会被悄悄改变。
11. ● 本地存档代价不变：换设备丢失、无云同步——免注册的另一面仍未处理。
12. ● fork 治理（本仓库特有）：上游两天四个大版本、直接推 main 的节奏下，fork 落后 3 个提交只是一天半的结果；没有固定的同步节奏和分支纪律，共同开发的“保持一致”很快会从技术问题变成人肉对账问题。

## 七、改进方案（v0.20.0 更新版，按优先级）

### P0：本周内做完，都是确认动作，不是开发任务

1. **确认 KV 绑定并做第一次读数。** 绑 `IFY_ANALYTICS_KV` → 玩完一局 → 在 KV 里看到当天日期开头的 key 和逐行 JSON，才算数据链闭环。之后每周固定读一次：完局率（game_complete / game_start）、分享率（share_click / game_complete）、瞥视观看率（glimpse 的 seen 比例），全部按年代拆开看（特别盯 c1955 的完局观感与 c2000 的序章漏斗）。
2. **给旧链接变更加一句玩家话。** 同局链接落地处写明“同一起点，两条人生”（或同等口径），把种子语义变更从“玩家自己发现对不上”改成“产品明说的设计”。
3. **README 定位语与影子实现对齐口径。** “作为平行线继续运行”后加注或改写（例如“以剪影方式继续”），在完整推演做出来之前，不暗示双线完整模拟。

### P1：用第一批数据决定，不要凭感觉排期

4. **完局漏斗哪里漏，哪里优先。** game_start 高、complete 低 → 先做轻局 / 时长（进程拍合并、平淡年合并的挂账该还了）；complete 高、share 低 → 先做卡面与钩子（“差一步”和猫线这类已被盲审验证的截图点，应进分享卡）；share 有、回流低 → 先做挑战横幅与对照卡。
5. **死亡观感真人验证（20–30 人试玩，只问三件事）：** 中途死亡的那一局，你觉得“这一生完整吗”？1955 年生局会不会觉得“怎么老是活不长”？序章 12 幕会不会觉得“怎么还没开始选路”？原话比问卷分数有用。
6. **序章补齐排期要诚实计价。** 三个年代各是一份写作工程，先补 1978（与主力人群父母辈重合、情感用法最强），1955 / 1965 排在其后，并公开说明节奏，不要让“逐轮补齐”变成无限期承诺。

### P2：把已欠的商业账还上

7. **珍藏付费立项条件改为“数据触发”。** 完局量达到增长文档的样本门槛（周完局 ≥300）后 2 周内上线珍藏小样并做价格 A/B；4 周转化 <0.3% 就停，转 B 端。这条在上一版就写了，这一版加上启动条件和死线。
8. **B 端小样先于 B 端平台（不变，但更紧迫）。** 死亡标定 + 父母进程是这一轮攒下的新弹药，教师手册的素材（世代生存曲线出处、父母进程口径）都是现成的；做 1 个引导版小样去谈 3–5 家机构，不要等功能齐。
9. **故事墙仍是 P2，但理由变了。** 上一版它排 P2 是因为没后端；现在收集端模式已跑通（同源 Function + KV），静态精选墙的技术成本更低了——它缺的只是授权征集这个运营动作，应在第一批真实玩家出现时就同步启动征集，而不是等“数据成立”后从零开始攒故事。

### P3：内容与系统（配额制，不再追总量）

10. 务农线设硬配额：下一轮内容包先补农民线的入行拍后中段与晚年供给，用盲读复验农民线不再垫底为验收，而不是“如实记垫底”就算交代。
11. 判词形状做一次小手术：不改规则，只针对金钱垫底 1% 的成因查一轮（是供给还是权重），结论写进 DEVLOG——连续两轮“只报不修”之后，第三轮必须二选一：修，或正式决定接受并说明理由。
12. 影子推演排进路线图但不定版号：账本 + `#world` 流已具备双线推演的原料，建议先做“影子关键节点与主线同规则掷骰、文本仍剪影”的半步，既缩小口径落差，又不背全量双线的内容债。

### 关于本 fork 的共同开发（单独一条，不是产品建议）

13. **同步节奏定死：** 上游保持现在这个速度的话，fork 每周至少同步一次（GitHub 的 Sync fork 或提同步 PR），共同开发的工作一律开分支、提 PR 回上游，不在两边 main 上对推。本评价分支基于 v0.16.1 旧主线，后续合并前需要先把上游 v0.20 合进来再提交新文档，避免拿旧基线盖新结论。

## 八、给作者的三句直话（复评版）

1. **两天四个大版本证明了产能，现在请证明克制。** 下一轮最有价值的“功能”，是一张只有三个数的读数表。
2. **死亡标定是这一轮最被低估的资产。** 它让这个游戏第一次有了“数据是真的”这句竞品拿不出的卖点——B 端材料和媒体稿应该先用它开路，而不是继续把它埋在 DEVLOG 里。
3. **农民线和判词形状已经“如实记”了两轮了。** 诚实记录是美德，但同一个问题记第三遍时，记录就会变成拖延的证据。
