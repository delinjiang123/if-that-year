本回应由开发总指挥逐条核对现行代码与账本后写定。口径先行：评价引用的数字是 2026-11-11 上午的账（5,838 条／6,039 台账／19 条职业主线）；现行账以本回应为准——**v0.60.126：条目 6,124、台账 6,325、注册行当 34、整线闭环 21 条**。

## 一、五项重点的核查结论

### 1. 首局 Hook 时机——评价成立，采纳（小片）
实查：影子瞥视站位为 30/40/50 岁，第一瞥不早于分家岁＋5（`firstGlimpseAge`），常规局 22 岁分家后要到 30 岁才第一次看见影子活着，中间隔着整个二十岁段，确实没有任何信号。开场与 og 文案已经把「另一条路」写在明处，所以问题不在「没说」，在「说了之后八年没动静」。
**动作**：分家点（22 岁路线分岔落定处）加一行轻提示，原文照评价建议微调：「你没走的那条路，也从这里开始了。」——不占年、不剧透、不动瞥视三站与随机流（呈现层一行字）。编为 CL-122，排在在途两片富贵尾巴之后、周末试玩之前落地，让朋友试玩直接验这一行有没有用。

### 2. 完成率漏斗与内部门槛——采纳为暂行参考，不作硬线
现行匿名统计只数三件事：来访、开局、完局（buy.html 隐私段已如实写明）。评价给的门槛表（开局到首分岔 60%+、首局完成 25%+ 等）是评价者自定的决策阈值、不是行业事实——这一点评价原文也写明了。本项目采纳它作**暂行内部门槛**，等第一批陌生人样本回来再校准；漏斗事件扩展（first_shadow_hint/shadow_peek/replay 等）排到周末试玩之后，先让试玩充当评价说的「第一轮可观察测试」，不为埋点挤试玩。

### 3. 反馈五分类＋大型开发准入——采纳，附一条本项目修正
分类表（定位／UX／叙事／模型／市场／个体偏好，评价表另含 Feature 请求一类）与本项目现行处理实际已大体合流，正式立为规矩：外部反馈先分类再决定动不动；大型开发准入条件照评价五条（≥3 名独立玩家同类问题／数据示明显流失点／暴露模型错误／动核心承诺／涉付费法务数据完整性），不满足进 backlog。
**修正**：准入制度管的是「外部反馈驱动的大活」。项目所有者本人的方向裁定、与玩家席（艾莉）的验收结论是既有决策通道，不受 3 人门槛约束——评价的初衷是防熟人偏好绑架开发，不是给所有者设卡。

### 4. 付费典藏「本机永久」表述——评价提醒的方向对，现行文案已合规，不另建 License 服务器
实查 buy.html 全文：没有出现「永久」字样；现行表述是「付一次，这台设备以后每一局走完都能导出」，且明写找回办法——解锁记在输码的浏览器里、码丢了凭付款收据补发、微信内打开的注意事项也写了。评价担心的「说过头」在现行文案里没有发生。
服务端 License（purchase_id/token/绑设备）**不采纳**：与产品伦理「人生内容默认留在本地、不上传」及一人运营的维护上限冲突；现行恢复路径（兑换码＋收据补发）对当前体量合称。若日后陌生人销量成规模，再按 Gate D 证据重议。

### 5. 存档版本契约——机制已有，只修一处文案
分享链接自 v0.18.0 起带内核版本位（k=3），旧链接打开同一种子不保证同一局，策略记在 DEVLOG。评价建议的准确表述「同一游戏版本、同一设置与同一种子可复现」与现行机制一致。唯一说过头的是 README 一句「同一种子同一段人生……任何一年都能重放出来对账」——本次存档推送中已改为同版本口径。

## 二、与现行优先级冲突处（不对齐不硬收）

- 评价六周计划 Week 4「禁止新增职业和大型系统」与所有者明示方针冲突：总量无上限（韩信点兵）、朋友正期待新职业、铁路/回收/邮政三条新线已于今日上线。**不采纳冻结**；本项目的顺序是扩盘与试玩并行，试玩（本周末）就是评价要的第一轮观察测试。
- 评价把「更多职业」列 P2 暂停区，同理不收：本项目的优先级是所有者定的「逻辑性与游戏性优先」，职业扩盘服务于「每次结果不同、结果与玩家有关」的产品方针，不属于无反馈的盲目扩系统——每条新线都过入口普查与人手二筛。
- 特商法页面、运营者信息：评价列 P0，与本项目存量待办一致（等所有者定运营者信息与购买文案终稿），在陌生人付费推广前必须落地；当前两笔自测属上线验证，不受此阻塞。
- 内容提示（疾病/离世等）与「不做心理判断」：后者现行判词纪律已守（判词只读账本、不评价玩家本人）；前者（首次进入前一页简短提示）采纳为待办小片，排 CL-122 之后，不弹窗、只在开始页放一行。
